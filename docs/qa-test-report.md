# 합성 인보이스 수직 흐름 QA 절차·결과 보고서

> 1–5절은 2026-08-20 당시 기록이며, 최신 검증 결과와 정정 사항은 6절을 따른다.

## 1. 목적과 범위

이 보고서는 `./scripts/demo`가 재현하는 로컬 수직 흐름을 절차서에 따라 확인한 결과다. 합성 XLSX 인보이스 입력부터 신고서 초안 검토·검증, XML/CSV/XLSX 출력까지의 정상 흐름과 두 가지 예상 실패 흐름을 다룬다.

다음 범위는 이 보고서의 검증 대상이 아니다.

- 실제 관세 문서와 개인정보
- 실제 UNI-PASS·관세청·uTradeHub 전송
- 공개된 최신 공식 XSD에 대한 적합성
- 브라우저 UI, 모바일·전장·로봇 기기 연동
- 운영 배포, 부하, 가용성, 백업·복구, 운영 모니터링

## 2. 실행 환경과 재현 명령

- 확인일: 2026-08-20 KST
- 데이터: 코드에서 생성한 합성 XLSX만 사용
- 저장소 제공 전체 검사: `./scripts/check`
- 수직 흐름 실행: `./scripts/demo --output-dir <비어 있는 임시 디렉터리>`
- 집중 회귀 검사: `backend/.venv/bin/pytest -q backend/tests/test_demo_flow.py`

재현 시 출력 디렉터리는 기존 결과와 섞이지 않도록 비어 있는 임시 디렉터리를 사용한다. 성공 흐름에서만 파일 3개가 생성되는지 확인하고, 예상 실패 흐름에서는 추가 출력이 생성되지 않는지 로그와 테스트로 확인한다.

## 3. 테스트 절차와 결과

| ID | 시나리오와 절차 | 기대 결과 | 2026-08-20 관찰 결과 | 판정 |
|---|---|---|---|---|
| QA-001 | 합성 XLSX를 업로드하고 파싱된 초안을 조회한 뒤, 사람이 국가코드·중량 등 누락값을 보완하고 검증·내보내기를 실행한다. | 품목 1건이 파싱되고 검증 오류가 0건이며 XML·CSV·XLSX 3개가 생성된다. | `invoice.parsed`, `declaration.review`, `declaration.validate`가 모두 `passed`; 산출물 3개 생성. | 통과 |
| QA-002 | XLSX 확장자에 손상된 바이트를 담아 업로드한다. | HTTP 422로 거부되고 임시 업로드 파일이 남지 않는다. | `http_status=422`, `rejected=true`, `upload_removed=true`. | 통과 |
| QA-003 | 구매자 국가코드를 3자리로, HS 코드를 4자리로, 총액을 품목 합계와 다르게 입력해 검증한다. | 세 필드 오류가 식별되고 내보내기 산출물이 생성되지 않는다. | `buyer_country_code`, `items[0].hscode`, `total_amount` 오류 3건; `outputs_written=false`. | 통과 |

QA-001에서 생성된 파일은 `GOVCBR830-demo.xml`, `declaration-demo.csv`, `declaration-demo.xlsx`다. 이번 실행 로그에는 파일별 크기와 SHA-256 앞 12자리가 기록되었지만, 이 값은 실행 결과 식별용이며 공식 규격 적합성의 증거로 사용하지 않는다.

## 4. 문제점·보완점 평가

### 이번 범위에서 확인된 실패

- 비정상 입력 두 건은 의도한 실패 조건에서 차단되었다.
- 이번 절차 실행에서 기대 결과와 다른 신규 결함은 관찰되지 않았다.
- 따라서 결함 수를 부풀리거나 상용 QA 성과로 표현하지 않는다.

### 남은 위험과 다음 보완 우선순위

| 우선순위 | 미검증 위험 | 보완 방법 | 현재 판정 |
|---|---|---|---|
| 1 | 브라우저에서 업로드→수정→내보내기 사용자 흐름이 깨질 수 있음 | 합성 파일을 사용하는 브라우저 E2E 시나리오 추가 | 미검증 |
| 2 | 단일 데모 명령이 PDF 파서 경로를 다루지 않음 | 개인정보 없는 합성 PDF fixture와 회귀 검사 추가 | 미검증 |
| 3 | XML이 최신 공식 스키마와 일치하는지 확인되지 않음 | 공식 XSD 확보 후 스키마 검증 추가 | 자료 미확보 |
| 4 | 부하·장기 실행·복구 특성이 알려지지 않음 | 운영 목표가 정해진 뒤 부하·복구 기준과 테스트 설계 | 범위 밖 |

## 5. 증거와 표현 한계

- 실행 코드: `backend/demo_flow.py`
- 자동 검사: `backend/tests/test_demo_flow.py`
- 재현 명령: `scripts/demo`, `scripts/check`
- 이 보고서가 직접 증명하는 것은 합성 로컬 흐름의 테스트 절차 수립, 실행 결과 기록, 예상 실패 분류, 미검증 위험 식별이다.
- 이 보고서는 상용 서비스 QA 경력, 실제 고객 데이터 검증, 운영 배포, 외부 시스템 전송 성공을 증명하지 않는다.


## 6. 2026-09-06 재검증 및 보완

기존 QA-003은 검증 실패 후 다운로드 API를 실제 호출하지 않아 서버 차단을 증명하지 못했다. 이번에는 XML/CSV/XLSX 세 엔드포인트를 직접 호출해 HTTP 400을 확인하도록 데모와 회귀 테스트를 보완했다.

| 검사 | 결과와 근거 |
|---|---|
| 전체 검사 `./scripts/check` | 백엔드 30개 테스트, ESLint, TypeScript/Vite 빌드 통과 |
| 상태·출력 회귀 | 수정 전 8개 실패 재현 → 수정 후 8개 통과. 초안 출력, 로컬 파일 이력의 제출 상태 전환, 제출·수리·반려 상태 재검증, 검증된 상태의 잘못된 내용 출력 차단 |
| PDF 실물 fixture | 합성 PDF 업로드 → 회사명·품목·금액 확인 → 국가코드 보완 → 검증 → 세 형식 출력 통과. 회사명 내부 Exporter/Buyer 단어 손상을 재현하고 수정 |
| CLI 합성 XLSX 데모 | 산출물 3개, 손상 파일 HTTP 422 및 정리, 검증 오류 3개와 출력 API 차단 3개 확인 |
| 브라우저 수동 자동조작 검사 | Chromium에서 XLSX 업로드·파싱 → 국가코드 누락 검증 실패 → US 입력·저장·검증 → Excel/XML 실제 다운로드 확인 |
| 수정 후 재검증 | 검증된 화면에서 CA로 수정하면 검증·다운로드 비활성화. 저장하면 초안으로 전환, 재검증하면 다운로드 복원 |
| 격리 데모 서버 | `scripts/serve-demo` 실행 후 health HTTP 200, 빈 신고서 목록 확인. 임시 DB와 업로드 폴더 사용 |

브라우저 검사는 이번 실행에서 확인한 결과이며 저장소에 상시 실행 E2E 테스트가 추가된 것은 아니다. 합성 XLSX UI 흐름과 합성 PDF API 흐름을 구분한다. 스크린샷은 로컬 `output/playwright/`에 남기며 Git에서는 제외한다.

남은 항목: 깨끗한 환경에서의 최초 설치, GitHub PR/CI 최신 상태, 공식 XSD 검증, 실제 고객 양식 다양성, 운영 배포·부하·복구. 빌드에는 번들 크기 경고가 있고 브라우저에는 Ant Design 사용 API의 deprecated 경고가 관찰되었다. 위 사용자 흐름을 중단하는 오류는 관찰되지 않았다.


## 7. 이미지 PDF 시제품 추가 검증

공통사항·란항목 OCR 시제품을 별도 경로에 추가했다. 백엔드 전체 36개 테스트와 프런트엔드 lint·빌드가 통과했다. 실제 브라우저 OCR, 수정, JSON 저장, 12열 복사를 확인했다. 합성 단일 사례의 결과와 누락·미확인 항목은 [시연 검증 기록](prototype-demo.md) 및 [정답 대조](demo-case/evaluation.json)를 따른다. 기존 절의 OCR 미지원 설명은 기존 파서 경로에 적용된다.
