# 이미지 PDF 자동 작성 시제품 시연

## 목적

현재 수출통관 실무에서 선적서류를 읽고 ecom 공통사항·란항목을 반복 입력하는 문제를 발견해 만든 개인 프로젝트다. 대표 이미지 PDF에서 전체 초안을 작성하고, 원문 근거와 누락을 확인해 수정하는 가능성을 보여준다.

## 실행

macOS와 Xcode Command Line Tools의 Swift 컴파일러가 필요하다. 기존 의존성 설치는 저장소의 `./scripts/bootstrap`을 따른다.

```bash
./scripts/setup-ocr
./scripts/serve-demo
```

다른 터미널:

```bash
cd frontend
npm run dev
```

`http://127.0.0.1:5173/preparation`을 연다. 이 경로는 기존 SQLite 신고서 관리 화면과 별도이며 임시 초안을 브라우저에서 검토한다. 새로고침하면 초안이 사라진다. JSON으로 보관할 수 있다. PDF는 로컬 처리 후 임시 파일을 삭제하며 외부 AI API를 호출하지 않는다.

## 3분 시연

1. **문제 설명:** 이미지 선적서류를 보며 공통사항과 품목 정보를 반복 입력한다. 기존에 Excel을 재가공해 12열을 붙여넣었고, 개인적으로 Gemini를 이용해 중간 정리를 줄였다.
2. **합성 PDF와 설정 불러오기 → PDF 읽고 전체 초안 작성:** 2쪽 이미지 PDF의 공통 16개·품목 12행을 확인한다. 공통 4개는 명시적인 가상 기본 설정이며 PDF 추출과 구분된다.
3. **원문 대조:** 중량 근거를 누르면 2쪽으로 이동한다. 공란인 10행 수량을 원문에서 찾아 `11`로 수정한다. OCR이 놓친 값을 자동으로 추측하지 않았음을 설명한다.
4. **검토 결과 확인:** 최초 확인 사항 14개가 수정 후 12개로 줄어든다. 남은 원산지코드는 실제 매핑을 확인하지 않았으므로 공란으로 유지하고 검토 완료 표시를 하지 않는다.
5. **전체 초안 JSON 저장 / 품목 12열 초안 복사:** 수정값·근거·초안 상태를 보관하거나 12열로 복사한다. 실제 ecom 적용 검증과 송신은 포함하지 않는다.

## 확인한 결과

동일한 합성 이미지 PDF 한 건에서 기존 텍스트 파서는 품목 0행, 새 OCR 경로는 12행을 반환했다. API 측정 1회는 1.22초였다. 이는 해당 기기·문서의 관측값이며 처리시간 개선율이 아니다.

정답 대조에서 공통 16/16개(문서 12개 + 설정 4개), 품목 12열 144칸 중 143칸이 일치했다. 공란과 반복값이 포함된 단일 사례이므로 일반 OCR 정확도로 해석하지 않는다. 10행 수량 `11`을 OCR이 누락했고 검토 항목으로 남겼다. 원산지코드는 이 12열 밖의 미확인 항목이다. 상세 기록은 [evaluation.json](demo-case/evaluation.json)에 있다.

검증: 백엔드 38개 테스트, 프런트엔드 lint·빌드 통과. 브라우저에서 실제 OCR 실행, 누락 수량 수정, 원문 표시, 검토 완료 잠금, JSON 다운로드, 수정값을 포함하는 12행×12열 클립보드 출력을 확인했다. 로딩 마크업 오류를 수정한 뒤 재실행에서 새 오류가 없었다. 빌드에는 번들 크기 경고가 남는다.

## 구현과 다음 확대 조건

Apple Vision OCR이 글자와 위치를 추출하고, Python 규칙이 대표 영문 라벨·표 열 위치를 필드에 연결한다. 프런트엔드는 원문과 각 값의 출처를 표시하며 사용자가 수정한다. 직접 OCR 모델을 학습하거나 범용 LLM 추론기를 개발한 것은 아니다. 사용 API: [Apple VNRecognizeTextRequest](https://developer.apple.com/documentation/vision/vnrecognizetextrequest).

현재 지원은 대표 영문 Invoice·Packing List의 단일 PDF이며 최대 10MB·12쪽이다. 임의 양식, 여러 문서의 복잡한 병합, B/L 대조, 자동 란 분류, 규격 길이 분할, 통관 의미 검증, ecom 입력은 미검증 또는 미구현이다. 문서와 프로필 값이 없으면 공란으로 남긴다. 신고 송신 직전까지의 전체 자동화는 장기 목표이며 현재 완료 범위는 이 로컬 시연이다.

다른 구조를 포함한 합성 문서 4건의 검증과 라벨 매핑 개선을 완료했다. [결과와 실패 원인](demo-cases/README.md)을 바탕으로 다음 개선을 결정한다. 같은 Mac의 별도 소스 복사본에서 새 의존성 설치·전체 검사·OCR 실행을 확인했다. 원격 반영 상태는 [PR 준비 문서](portfolio-pr-draft.md)에 기록한다. 사용자에게 필요한 다음 단계는 3분 시연을 직접 해보며 업무 설명과 구현 범위를 자신의 말로 연결하는 것이다.
