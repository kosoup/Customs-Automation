# 면접 3분 시연 대본

## 0:00–0:30 업무 문제

"현재 수출통관 업무를 하고 있습니다. 이미지로 받은 선적서류를 읽고 ecom에 공통사항과 품목 정보를 입력합니다. 품목이 많으면 엑셀로 재가공해 붙여넣는데, 이 반복 정리에 자동화 가능성을 발견했습니다."

## 0:30–1:20 자동 작성과 근거

"그래서 개인 프로젝트로 이미지 PDF를 읽어 공통사항과 품목 초안을 작성하는 도구를 만들었습니다. 여기서 네 항목은 기본 설정이고 나머지는 문서에서 추출합니다. 각 값의 원문 페이지를 함께 확인할 수 있습니다."

합성 PDF와 설정을 불러오고 초안 작성 버튼을 누른다. 중량 근거에서 2쪽을 보여준다.

## 1:20–2:00 실패 확인과 수정

"이 문서에서는 OCR이 수량 11을 놓쳤습니다. 잘못된 값을 채우는 대신 빈칸으로 표시하게 했습니다. 원문을 보고 수정하면 저장·복사 결과에도 반영됩니다."

10행 수량을 수정하고 JSON을 저장한다. 미확인 원산지코드 때문에 검토 완료로 표시하지 않는다.

## 2:00–2:40 검증과 판단

"서로 다른 합성 문서 세 건을 비교했습니다. 열 순서가 바뀐 문서는 추출됐지만, 항목 이름이 달라진 문서는 글자를 읽고도 필드 연결에 실패했습니다. OCR 오류와 매핑 오류를 구분하고, 항목 이름 연결 규칙을 보완했습니다. 개선 후에는 새로 만든 2쪽 문서도 추가 확인했습니다."

`docs/demo-cases/README.md` 표를 보여준다. 개선 전 3건과 개선 후 4건을 구분하고 일반 정확도로 표현하지 않는다.

## 2:40–3:00 범위와 역할

"현재는 로컬 시제품이며 ecom 연계와 실제 업무시간 절감은 아직 확인하지 않았습니다. AI 코딩 도구의 도움으로 구현했고, 저는 업무 흐름·입력 항목·예외를 설명했습니다. 이 처리 흐름과 실패 사례를 직접 설명할 수 있도록 정리하고 있습니다."

본인이 아직 직접 하지 않은 검증이나 구현을 혼자 수행했다고 말하지 않는다. 다음 질문을 자신의 말로 답하는 연습을 한다.

1. 기본 설정과 문서 추출을 왜 나눴나? 문서에 없는 값을 읽어낸 것처럼 보이지 않게 하려고.
2. 세 번째 문서가 실패한 이유는? 글자 인식 뒤 항목 이름을 연결하는 규칙이 제한적이기 때문.
3. 다음에 무엇을 고칠 것인가? 남은 OCR 누락과 미지원 양식을 재현하고, 원인에 맞춰 인식·매핑 규칙을 보완.
4. 무엇을 구현한 프로젝트인가? 수기로 옮겨 적던 공통·품목 정보를 PDF에서 초안으로 작성하고, 근거 대조·누락 확인·수정·출력까지 연결한 시제품. 합성 문서 정답 대조로 확인했으며 시간 절감률은 주장하지 않음.
5. 실제 운영하려면? 실제 입력 규칙·ecom 연계, 여러 양식의 검증, 문서 보관·오류 대응 절차를 추가 확인해야 한다.
