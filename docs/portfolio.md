# 업무 자동화·솔루션 운영 포트폴리오

## 문서 검증과 면접 준비

[검증 결과·실패 원인](demo-cases/README.md) · [3분 대본](portfolio-demo-script.md) · [GitHub PR 준비 상태](portfolio-pr-draft.md)

합성 이미지 PDF 4건의 정답 대조와 매핑 실패의 수정 전후를 기록했습니다. 포트폴리오는 실무 문제 발견 → 자동 초안 작성 → 오류 확인·개선의 과정을 보여줍니다. 시간 비교는 완료 조건에 포함하지 않습니다. 최신 검증·게시 상태는 PR 준비 문서에서 확인합니다.

## 최신 시연 범위

이전 텍스트 PDF/XLSX 흐름에 이미지 PDF OCR 시제품을 추가했다. 현재 면접 시연은 [이미지 PDF 자동 작성 시연](prototype-demo.md)을 우선한다. 아래 기존 DB·파일 출력 시연은 별도 기능이다.

> 현재 수출통관 업무에서 이미지 선적서류를 확인하고 반복 입력하는 부분에 자동화 가능성을 발견했습니다. 개인 프로젝트로 PDF를 읽어 공통사항과 품목 초안을 작성하고, 각 값의 원문 근거와 누락을 확인하는 흐름을 구현했습니다. 합성 사례에서는 12행을 추출했고, OCR이 놓친 수량 한 칸은 사람이 수정하도록 표시했습니다. 현재 대표 양식의 가능성을 검증한 단계이며 실제 ecom 연계와 현업 효과 측정은 아직입니다.

## 한 문장 소개

**현재 수출통관 실무에서 경험하는 서류 확인·반복 입력 과정에 착안해 만든, 인보이스 기반 신고서 초안 작성·검증 개인 프로젝트.**

지원 직무는 업무 자동화·솔루션 운영이다. 보여줄 역량은 문서 입력 처리, 오류 재현, 데이터 검증, 상태 관리, 재현 가능한 실행 절차다. 앱 자체는 규칙 기반 파싱이며 LLM을 호출하지 않는다.

## 문제와 해결 범위

현재 수출통관 업무를 담당하고 있다. 본인이 설명한 실제 업무 흐름은 다음과 같다.

선적서류 수령 → B/L·Invoice 확인 → 필요한 자료를 눈으로 확인 → 통관프로그램에서 신고서 작성 → 관세청 신고 → 수리 → 수출통관필증 발급.

이 중 서류에서 정보를 확인하고 신고서에 옮겨 적는 부분에 자동화 가능성을 발견해 개인 프로젝트로 구현했다. 현재 구현은 인보이스에서 값을 추출해 초안을 만들고 사람이 검토·수정한 뒤 필드 검증과 파일 출력을 수행하는 범위다. B/L 자동 추출·Invoice 대조, 실제 사용하는 통관프로그램 입력 연계, 관세청 신고·수리·필증 발급은 구현·검증한 성과에 포함하지 않는다.

개인 프로젝트는 합성 데이터로 검증했다. 현업 적용 여부와 시간 절감·오류 감소 효과는 아직 확인하지 않았다.

### 면접 소개 초안

> 현재 수출통관 업무를 하면서 선적서류의 B/L과 Invoice를 확인하고, 필요한 정보를 통관프로그램에 입력해 신고서를 작성하고 있습니다. 이 과정에서 반복 입력을 자동화할 수 있겠다고 생각해 개인 프로젝트를 만들었습니다. 우선 인보이스에서 정보를 추출해 신고서 초안을 만들고, 사람이 검토·수정한 뒤 검증하고 파일로 내보내는 흐름을 구현했습니다. 현재는 합성 데이터로 동작을 검증한 단계입니다.


```
PDF/XLSX → 파서 → 필드 정규화 → SQLite 초안
                                  ↓ 사람의 검토·수정
                              서버 필드 검증
                                  ↓ 통과 시
                          XML / CSV / XLSX 파일
```

FastAPI가 업로드·DB·검증·출력을 담당하고 React 화면이 검토 과정을 제공한다. PDF는 pdfplumber, XLSX는 openpyxl, XML은 lxml을 사용한다.

## 면접에서 보여줄 3분 시연

사전 준비: `./scripts/serve-demo`로 임시 DB의 API를 실행하고 다른 터미널에서 `cd frontend && npm run dev`로 화면을 연다. 실제 고객 자료 대신 `backend/tests/fixtures/synthetic-invoice.xlsx`를 사용한다. API 키는 불필요하다.

| 시간 | 동작 | 설명할 핵심 |
|---|---|---|
| 0:00–0:30 | 문제와 범위를 소개 | 반복 입력의 초안 생성을 자동화하고 최종 검토는 사람이 수행 |
| 0:30–1:00 | 합성 인보이스 업로드, 파싱 미리보기 | 원본에서 추출된 값과 누락값을 구분 |
| 1:00–1:30 | 초안에서 검증 실행 | 국가코드 누락 오류를 확인하고 다운로드가 막히는 것을 시연 |
| 1:30–2:00 | 구매자 국가코드 `US` 입력, 저장·검증 | 변경 후 재검증해야 출력이 열리는 절차 설명 |
| 2:00–2:30 | XML·Excel 다운로드 | 결과를 파일로 생성하며 실제 신고 전송과 구분 |
| 2:30–3:00 | `./scripts/check` 결과와 결함 수정 소개 | 실패 재현 테스트를 먼저 만들고 수정 후 통과시킨 근거 제시 |

이 기존 시연의 합성 PDF는 텍스트 기반이다. 이미지 PDF OCR은 위의 별도 시제품 경로에서 검증했다.

## 이력서 프로젝트 문구 초안

**Customs Automation — 인보이스 기반 신고서 초안 작성·검증 도구**

- 현재 수출통관 업무의 서류 확인·반복 입력 과정에서 자동화 가능성을 발견해 개인 프로젝트로 개발.
- PDF/XLSX 인보이스에서 신고서 초안을 생성하고 사용자 검토·필드 검증 후 XML/CSV/XLSX로 내보내는 흐름 구현(FastAPI·React·SQLite).
- 검증 실패 초안의 출력, 파일 작업과 외부 제출 상태 혼동, 제출 상태의 재검증 전환 문제를 API 회귀 테스트로 재현하고 보완.
- 합성 데이터와 격리된 DB를 활용한 테스트·데모 및 실행·장애 점검 절차 정리.

이 문구는 프로젝트의 구현 내용을 설명한다. 본인의 실제 역할·개발 기간·AI 도움 범위는 사실에 맞게 추가한다. 코드의 흐름과 테스트를 직접 설명할 수 있는지 확인하기 전에는 독자 설계·운영 성과를 주장하지 않는다.

## 설명할 수 있어야 하는 다섯 가지

1. **왜 업로드 직후 출력하지 않는가?** 파서가 국가코드 등 일부 값을 채우지 못할 수 있다. 초안 검토와 서버 검증을 거쳐야 한다.
2. **프런트엔드에서만 막으면 충분한가?** API를 직접 호출할 수 있으므로 서버도 상태와 내용을 확인한다. 화면의 저장하지 않은 수정은 다운로드를 잠근다.
3. **어떤 결함을 어떻게 고쳤는가?** 빈 초안 출력, 파일 이력의 제출 상태 변경, 종료 상태 재검증을 실제 API 테스트에서 실패시킨 뒤 수정했다. PDF 회사명 손상도 합성 문서로 재현했다.
4. **테스트는 어디까지 증명하는가?** 합성 자료의 로컬 흐름과 지정된 오류를 검증한다. 실제 고객 양식 전체, 부하, 운영 배포, 공식 XSD 적합성을 증명하지 않는다.
5. **다음 요구가 들어오면 어떻게 대응하는가?** 실패 문서의 개인정보를 제거한 재현 자료를 만들고 파싱·매핑·검증 중 어느 단계에서 값이 달라졌는지 확인한 후 회귀 테스트를 추가한다.

## 운영 점검 순서

| 증상 | 확인 | 조치와 한계 |
|---|---|---|
| 앱 실행 실패 | Python 3.12·Node 22 및 `./scripts/bootstrap` 결과 | 설치 후 `./scripts/check`로 확인; 기존 DB·업로드는 삭제하지 않음 |
| 화면에서 API 호출 실패 | API `/api/health`, `VITE_API_BASE_URL`, `CORS_ORIGINS` | 실제 사용하는 프런트엔드 origin과 API 주소 일치 확인 |
| 파일 업로드 거절 | PDF/XLSX 여부, 10MB 기본 한도, 오류 응답 | 손상 파일은 422 및 임시 업로드 정리를 테스트함 |
| 파싱 값 누락 | 원본 → 미리보기 → 저장된 초안 비교 | 해당 양식의 합성 재현 파일을 확보; OCR은 별도 시제품 경로에서 제한적으로 지원 |
| 다운로드 불가 | 미저장 변경, 초안 상태, 검증 오류 확인 | 저장·수정·재검증; API도 오류 초안 출력 차단 |
| 외부 조회 불가 | 선택적 API 키·연계 계약 여부 | 키를 로그나 이력서에 붙이지 않음; 외부 연결 성공은 미검증 |
