# 03. 송신 직전까지 자동화 — 순서별 작업 목록

상태: 사용자 합의에 따라 대표 사례로 가능성을 보여주는 시제품을 우선 제작한다. 로컬 계획이며 기능 구현·GitHub 발행을 뜻하지 않는다.
기준: `ecom-preparation-spec.md`. 기존 12열 복사 중심 계획을 대체한다.

| 순서 | 작업 | 완료 조건 |
|---|---|---|
| T01 | 공통·란 전체 항목과 적용 경로 확인 | 항목별 서류/설정/계산/판단 출처를 정리. ecom 공통항목 입력, 품목 일괄입력, 분류·저장 경로와 시험 환경 확인. 미확인 사항 명시 |
| T02 | 합성 서류 묶음과 전체 정답 작성 | 공통항목·12열·추가 란항목·기본값·예외 포함. 이미지 PDF, 텍스트 PDF, Excel 대표 사례. 정상 건과 충돌·누락 건 구분 |
| T03 | 기존 코드 차이와 설계 확정 | 전체 필드 모델·OCR·설정·검증·ecom 적용의 변경 위치, DB 마이그레이션 영향 확인. 기존 변경 보존 |
| T04 | OCR·문서 해석 및 자동 작성 | 이미지 PDF부터 공통·품목 추출, 문서 간 연결, 설정값 적용, 계산과 근거 추적. 합성 정답과 비교해 도구 선택·개선 |
| T05 | ecom 자동 적용 연결 | 공통항목과 란항목을 적용하고 기존 분류·저장 기능까지 연결. 12열 붙여넣기는 일부 전달 수단. 실제 시험 환경에서 저장 결과 확인 |
| T06 | 예외 처리와 전체 흐름 검증 | 정상 건 자동 작성, 불확실·충돌 건 검토, 수정 후 재검증, 중단·재시도 시 중복·잘못된 건 적용 방지. 송신 버튼은 실행하지 않음 |
| T07 | 동작 검증·포트폴리오 | 합성 정답 대조, 누락·매핑 실패와 개선 결과를 기록. 실무 문제와 자동 작성 흐름을 설명. 시간 비교는 필수 조건에서 제외 |

시제품 순서는 T02 기준자료 → T03 차이 확인 → T04 전체 초안 작성 → T06 중 로컬 검토 → T07 검증 기록·설명 정리다. T01의 항목 출처 확인은 진행하되, T05 ecom 연결은 선택적 후속 검증으로 둔다. 품목만으로 범위를 줄이지 않는다. 이미지 PDF 4건의 정답 대조와 회귀 검사를 완료했다. 상세 기록은 demo-cases/README.md를 따른다.

## 검증과 기존 코드

`workflow-comparison.md`의 XML 의미·값 전달 문제는 여전히 미해결이다. ecom 입력 자동화와 자체 공식 XML의 적합성은 별도로 검증한다. 프로젝트 AGENTS.md에 따라 코드 검사와 영향받는 UI 검증을 수행한다. 사용자 DB·업로드·기존 변경을 보존하고 합성 문서와 분리된 시험 DB를 사용한다. 실제 문서·인증정보를 커밋하지 않는다. 외부 AI 서비스와 비용은 아직 결정하지 않았다.


## 시제품 구현 결과

로컬 OCR → 공통·란 초안 → 근거 대조·수정 → JSON/12열 복사 경로와 대표 사례 검증을 완료했다. 구체적 범위·실패 사례는 [시연 기록](prototype-demo.md)을 따른다. 기존 목록의 범용 문서 처리·실제 ecom 연계까지 완료했다는 뜻은 아니다.
