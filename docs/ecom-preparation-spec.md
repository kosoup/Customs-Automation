# 02. 선적서류에서 ecom 송신 직전까지 — 1차 명세

상태: 사용자 합의에 따라 가능성 검증용 시제품으로 범위 조정. 최종 지향점은 송신 직전 전체 자동화이며, 이번 납품은 대표 서류에서 공통·란항목 전체 초안을 작성하는 시제품이다. 구현 완료 또는 ecom 호환 검증을 뜻하지 않는다.
근거: 이 세션의 사용자 설명과 `workflow-comparison.md`의 기존 코드 비교. 현재 법규나 ecom 최신 사양을 확인한 문서가 아니다.

## 문제와 목표

사용자는 현재 수출통관 업무를 수행한다. 서류에서 값을 찾고 신고 항목에 맞게 옮기고 대조하는 반복 작업을 줄이려 한다. 지원 직무는 업무 자동화·솔루션 운영이다.

기존에는 받은 엑셀을 재가공해 ecom에 일괄 붙여넣었다. 사용자 본인은 OCR 확장프로그램으로 문서 영역을 직접 선택해 추출하거나, Gemini에 프롬프트를 입력해 표 형태의 결과를 받아 엑셀에 복사한 뒤 ecom에 붙여넣었다. Gemini에 전달한 정확한 파일 형식은 미확인이다. 동료들의 현재 방식은 사용자의 추정이다.

사용자가 명확히 정정한 목표는 PDF 읽기·OCR → 서류 해석 → 공통항목과 란항목 전체 작성 → ecom 자동 적용·란 분류·저장 → 송신 직전 준비이다. 12열 복사는 품목 전달 수단 중 하나이며 최종 목표가 아니다. 정상 건은 자동으로 작성하고, 판독 실패·정보 부족·충돌 등 예외를 검토 대상으로 구분한다. 시간 절감·오류 감소는 아직 측정하지 않았다.

## 공통항목과 자동 적용

공통항목도 이번 목표에 포함한다: 환급신청인, 간이자동정액환급여부, 구매자코드, 목적국, 구매자, 제조자, 거래구분, 결제방법, 인도조건, 통화단위, 운임비, 기타금액, 총금액, 중량 및 카톤수. ecom이 통관전환으로 채우는 설정값도 전체 작성 흐름에서 확인한다.

각 항목의 값은 서류 추출, 거래처·기존 설정, 계산, 예외 판단 중 어디서 오는지 구분하고 근거를 연결한다. PDF에 없는 값을 모두 OCR로 얻는다고 가정하지 않는다. 고정값의 적용 조건과 예외, 문서 간 충돌 시 우선순위는 앞으로 확인한다.

란항목에는 아래 12열뿐 아니라 사용자 설명의 원산지·원산지코드와 분류 후 결과도 포함한다. 전체 순중량과 란별 순중량을 구분한다. 12열에 없는 항목의 입력 경로도 확인해야 한다.

이번 시제품에서 ecom 직접 연결은 가능하면 별도 시험하고, 불가능하면 미구현으로 명시한다. 공통·란항목을 모두 작성하는 범위는 유지한다. ecom 자동 적용 방식은 아직 미확정이다. 기존 일괄 붙여넣기는 사용 경험이 확인됐지만 공통항목 입력·저장까지의 자동 제어는 검증하지 않았다. 공식 연계·가져오기 기능 또는 UI 자동화를 실제 환경에서 조사하고 선택한다. 자체 앱에서 초안만 완성되면 중간 단계이며, 전체 목표 완료로 보지 않는다.

## 대표 업무와 범위

- GIF 이미지로 받은 서류를 기존 프로그램이 하나의 PDF로 합치는 경우가 많았다. PDF 또는 Excel로 직접 받기도 했다.
- 이미지 기반 PDF를 핵심 입력으로 삼고 텍스트 PDF·XLSX도 다룬다. GIF 합치기 자체는 이번 범위에서 제외한다.
- ecom 통관전환 시 상당수 고정값이 채워진다. 공통항목도 서류·설정·계산 결과를 사용해 자동 작성한다.
- 품목이 많을 때(사용자 표현: 란이 10줄을 넘으면 거의) 엑셀에서 ecom으로 일괄 붙여넣는 경로를 사용했다. 10줄은 프로그램 제한이 아니다.
- 공통항목·란항목 적용, 기존 란 분류 기능 실행 및 저장까지 자동화 대상으로 둔다. 관세청 송신 자체와 수리·필증 발급은 제외한다.
- 란 분류는 옵션을 선택한 뒤 ecom이 자동 처리했다. 사용자가 기억한 긴 규격의 다음 칸 이동은 편의 옵션 예시이며, 실제 란 묶기 기준은 미확인이다. 50글자를 확정 제한으로 구현하지 않는다.

## 품목 전달에 사용할 기존 12열 구조

아래 순서는 사용자 확인 사항이다. 열 이름 행 포함 여부, 클립보드의 구분 문자, 숫자 표시 형식·길이 제한은 실제 붙여넣기 전 확인해야 한다.

| 순서 | 열 | 처리 원칙 |
|---|---|---|
| 1 | 규격1 | Description 상세 정보. 파트넘버·시리얼넘버·제품코드 등이 포함될 수 있음 |
| 2 | 규격2 | 자유 사용. 특정 종류의 번호 전용으로 고정하지 않음 |
| 3 | 규격3 | 자유 사용. 임의 잘라내기나 확인되지 않은 길이 기준 자동 분할 금지 |
| 4 | 수량 | 원문에서 추출. 읽기 실패한 품목을 조용히 버리지 않고 확인 대상으로 표시 |
| 5 | 단가 | 원문 값을 보존하고 수정 가능 |
| 6 | 금액 | 원문 값을 보존. 수량×단가와 다를 때 알림, 자동 덮어쓰기 금지 |
| 7 | FTA발급여부 | Y/N/미확인 구분. 근거와 확인된 규칙으로 작성하고 불명확하면 검토 |
| 8 | FTA발급협정코드 | Y이면 근거가 확인된 코드 필요, N이면 빈칸. 106은 예시일 뿐 고정값 아님 |
| 9 | 세번부호 | 서류 값을 우선 추출. 문자열로 보존하여 선행 0 유지. 누락 시 추측하지 않음 |
| 10 | 품명 | 서류 값을 우선 추출, 수정 가능 |
| 11 | 거래품명 | 서류 값을 우선 추출, 수정 가능 |
| 12 | 순중량 | 사용자 경험상 대부분 빈칸, 필요 시 수기 입력. 빈칸을 0으로 대체하지 않음 |

세번부호·품명·거래품명은 체감상 서류 95%, 직접 판단 5%라는 설명이며 측정 통계가 아니다. 규격1~3 배치는 자유라는 사실만 확정했다. 초안 기본 배치는 Description을 규격1에 보존하고 규격2·3을 사용자가 편집하는 방안을 제안하며, 실제 길이 제한 확인 전 잘라내지 않는다.

FTA 판단 근거는 서류의 협정 문구와 원산지증명서 포함 여부 등이다. 첨부 여부만으로 Y나 협정코드를 확정하지 않는다. 문구·문서 페이지와 코드 매핑 근거를 연결한다. 확인된 규칙으로 자동 작성하고 불명확한 경우 검토를 요청한다. 정보 없음은 N과 다르다. 코드 매핑과 판단 기준은 아직 미확정이며 근거 없는 코드를 생성하지 않는다.

복사 형식은 탭으로 열을 나누고 줄바꿈으로 행을 나누는 TSV를 구현 후보로 둔다. Excel에서 12열로 펼쳐지는지 먼저 검증한다. 셀 내부 탭·줄바꿈은 열·행을 깨뜨리지 않도록 처리하고 원문은 별도로 보존한다. 빈 마지막 순중량 칸도 열 위치를 유지한다. Excel에서 수식으로 해석될 수 있는 문서 문자열은 실행되지 않게 다루며 ecom에 전달되는 값도 대조한다. 정확한 직렬화 규칙은 합성 데이터 검증에서 결정한다.

## 검토 화면과 상태

- 원문 페이지와 품목 표를 함께 볼 수 있게 한다. 가능하면 추출한 행·값의 페이지 출처를 연결한다.
- 이미지 PDF에서 아무것도 읽히지 않으면 빈 성공 결과를 반환하지 않고 실패·재확인 상태를 표시한다.
- 누락·중복 후보, 숫자 판독 불확실, 금액 불일치, FTA 미확인 등을 표시한다. 모델의 자신감 숫자만으로 신뢰를 주장하지 않는다.
- 모든 셀을 사람이 다시 입력·승인해야 하는 흐름을 전제로 하지 않는다. 정상 건은 자동 작성하고 누락·충돌·판독 실패는 해당 근거와 함께 검토 대상으로 표시한다. 수정 시 관련 검증을 다시 수행한다.
- 준비·확인·복사 상태와 관세청 접수 상태를 구분한다. 복사를 신고 완료로 표시하지 않는다.
- 외부 OCR/AI 제공자와 비용은 아직 정하지 않았다. 실제 고객 문서 전송이나 API 사용은 이 명세로 승인된 것이 아니다. 개발 자료는 합성 문서로 준비한다.

## 완료 기준과 검증 단계

1. 대표 합성 서류 묶음과 공통항목·란항목 전체 정답을 마련한다. 고정 설정, 문서 추출, 계산, 예외의 출처를 구분한다.
2. 이미지 PDF·텍스트 PDF·XLSX에서 공통·품목 값을 추출하고 누락된 행과 숫자 오류, 문서 간 충돌을 검출한다. 정상 사례와 불명확한 사례를 함께 평가한다.
3. 정상 사례는 수동 재가공 없이 공통·란항목을 자동 작성한다. 예외는 임의 값을 넣지 않고 검토 대상으로 남긴다. 12열 직렬화 검증은 이 단계의 일부이다.
4. 후속 통합 검증(이번 시제품 완료의 필수 조건 아님): 실제 ecom 시험 환경에서 통관전환 이후 공통·란항목 적용, 분류, 저장된 값까지 정답과 대조한다. 관세청 송신은 실행하지 않는다. 시험 환경이 없으면 전체 완료로 표시하지 않는다.
5. 합성 정답과 추출값을 대조하고 누락·매핑 실패·수정 흐름을 기록한다. 사용자 결정에 따라 시간 비교는 이번 포트폴리오 완료 조건에서 제외한다. OCR 문자 정확도만으로 전체 성능을 주장하지 않는다.

OCR 이력 정정: ecom에서 PDF를 열 때 기본 OCR이 실행된 것이 맞다. 사용자는 그 결과에 만족하지 못해 별도 Chrome OCR 확장프로그램을 설치하고 영역을 선택해 추출했다. 체감 신뢰도 약 30%는 측정 정확도가 아니다. 기존 코드의 테스트 통과와 실제 이미지 문서 처리·ecom 전달은 별도 검증 대상이다.

## 현재 남은 확인 사항

우선 공통항목별 출처·기본값·예외와 ecom 자동 적용 가능 경로를 조사한다. 서류 묶음 구성, 계산·반올림 규칙, 원산지·FTA 매핑, 란 분류 옵션, 저장 후 값 확인 방법을 순서대로 정한다. ecom 접근 가능한 시험 환경이 필요하며 환경 부재는 ecom 연결 미검증으로 기록하되, 전체 항목 초안 시제품의 완료를 막지는 않는다.

## 이번 시제품의 완료 기준

대표 이미지 PDF를 넣어 공통·란항목 전체 초안을 만들고 근거·누락·불확실한 값을 확인 및 수정할 수 있어야 한다. 정답 대비 최초 추출 결과, 수정 항목, 소요시간을 기록한다. 다양한 업체 양식과 장기 운영 대응은 후속이다. ecom 적용까지 성공한 것으로 표현하지 않는다.

첫 기준 자료: `demo-case/README.md`, `demo-case/expected.json`, `../output/pdf/synthetic-shipping-scan.pdf`. 현재는 입력과 정답을 준비했으며 자동 추출 성능을 검증한 것이 아니다.
